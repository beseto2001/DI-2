## 1. 데이타 개요 (EDA 요약)
- 행/열: 1500 x 8
- 주요 컬럼: order_id, customer_age, category, channel, price, quantity, amount, return_amount

## 2. 진단 결과    
- 결측: amount(약 3%, app 채널에 쏠림 → MAR 의심), price(0.3%, 소수 — MCAR일 가능성/행제거 고려)
- 이상치(IQR):
    customer_age(0살 2건, 5살 1건, 999 3건 — 입력 실수?)
    quantity(200 1건 — 대량구매, 도매?)
    amount(50,000,000 — 단일 거래)
- 의심되는 결측 유형: amount는 app 채널에 쏠림 (MAR 처리 가능성)

## 3. 결측·이상치 처리 결정

> **방침:** 물리적으로 불가능한 값과 도메인 밖의 값은 NaN으로 바꾼 뒤 중앙값으로 대체하고,
> 비즈니스적으로 가능성이 있는 극단값은 유지하되 플래그로 표시한다.

## 가. 처리 요약

| 컬럼 | 이슈 | 처리 | 방법 |
|:---|:---|:---|:---|
| `customer_age` | 1 미만, 110 초과 (999, 0) | NaN → 중앙값 대체 | 전체 중앙값 (33) |
| `quantity` | IQR 이상치 (200) | NaN → 중앙값 대체 | 전체 중앙값 |
| `amount` | IQR 이상치 (50,000,000 등) | 유지 + 플래그 | `amount_outlier` = 1 |
| `amount` | 결측 | 중앙값 대체 | 채널별 중앙값 |
| `price` | 결측 | 중앙값 대체 | 카테고리별 중앙값 |

---

## 나. 판단 근거와 한계

| 이슈 | 근거 | 한계 |
|:---|:---|:---|
| `customer_age` 999, 0 | 물리적으로 불가능한 값 → 입력 오류 추정 | 실제 나이 복원 불가, 5~14세는 범위 안이라 그대로 남음 |
| `quantity` 200 | 일반 고객 도메인 밖의 값 | 대체 후 `amount`를 재계산하지 않아 `price × quantity`와 불일치 |
| `amount` 이상치 | 극단값이라도 도매 등 비즈니스 가능성 보존 | IQR(k=1.5) 기준 플래그가 145건 — 정상 고가 주문까지 포함됨 |
| `amount` 결측 | app 채널 결측 비율이 높음 → MAR 가설에 부합 | 채널별 중앙값이 둘 다 79,900으로 같아 채널 구분 효과 없음 |
| `price` 결측 | 결측 0.3%로 적고 카테고리별 가격대 보존 | 카테고리별 중앙값이 모두 49,900으로 같아 카테고리 구분 효과 없음 |

### 4. 검증

- 처리 전후 컬럼별 결측 수 비교 → 처리 후 결측 0 확인 (설계상 NaN 유지가 필요한 컬럼 제외)
- 처리 후 `customer_age` 범위가 1~110 안에 있는지 확인  → 정상
- `amount_outlier` 플래그 건수 확인
